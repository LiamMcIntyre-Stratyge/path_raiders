<objective>
Wire progression end-to-end through the UI: exchange levels at match start over the existing realtime channel (clamped), thread them into the live battle, fix the stale stat display, and bind the provided upgrade-screen design to the progression service.

Purpose: This is the cross-participant PROG-03 surface (both clients fight at each other's persisted, clamped levels — D-11/D-12) plus the PROG-01/02 spend UI. It reuses the byte-preserved P10 wire protocol additively (a new `loadout` event on the placement channel, never touching the `game:roomId` battle protocol). The manual two-client parity check (mirroring P10's D-16 gate) is the human verification that opponent stats actually render correctly.

Output: Level exchange + clamp in PlacementScene, level pass-through to GameScene's createWorld, level-resolved LoadoutScene stat display, an UpgradeScene bound to the provided design, and a passing two-client parity gate.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| opponent client → loadout broadcast | Opponent supplies a level map over the realtime channel; untrusted, must be clamped before use |
| client → upgrade screen → upgrade_spend | The UI displays a mirrored cost but the spend is authorized server-side; the client never sends an amount |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-10 | Tampering / DoS | opponent sends level 999 or unknown unit id over loadout | mitigate | `clampLevels` in the loadout receive handler clamps to [1, MAX] and drops unknown ids before any sim use (D-12); resolver also clamps internally |
| T-12-11 | Tampering | client tries to display/spend a forged cheaper cost | mitigate | UPGRADE_COSTS is display-only; the spend goes through upgrade_spend which derives the cost server-side and ignores any client amount (PROG-04, plan 02) |
| T-12-07 | Spoofing | client claims it owns a higher level than it actually upgraded | accept (interim) | Clamp-only guard this phase (D-12); server-side ownership-of-level validation (signed report) deferred to P14 — accepted interim risk, mirroring Phase 11 D-05/D-06 |
| T-12-12 | Tampering | wire-protocol regression breaking the battle channel | mitigate | `loadout` is an ADDITIVE event on the placement channel; the byte-preserved `game:${roomId}` battle protocol is untouched (P10 D-04) |
</threat_model>
