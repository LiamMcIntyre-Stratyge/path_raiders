Create `supabase/migrations/20260614000000_progression.sql` (timestamp strictly later than the P11 `20260613061943` migration so it layers on top — assume P11 is applied first).

Schema: `create table public.upgrades (user_id uuid not null references auth.users(id) on delete cascade, scope text not null check (scope in ('unit','tower')), target_id text not null, level int not null default 1 check (level >= 1), primary key (user_id, scope, target_id))` (D-15). `alter table public.upgrades enable row level security`. One policy only: `create policy upgrades_select_own on public.upgrades for select using (auth.uid() = user_id)` — NO insert/update/delete client policy (deny-by-default, Pitfall 6). Add `grant select on public.upgrades to authenticated` if the project's grant convention (see 20260613062000_table_grants.sql) requires it; mirror the P11 table-grant approach.

RPC `public.upgrade_spend(p_scope text, p_target_id text) returns jsonb`, mirroring spend_unlock: `language plpgsql security definer set search_path = ''`; declare `v_owner uuid := auth.uid()`, `v_cur_level int`, `v_new_level int`, `v_cost bigint`, `v_bal bigint`, `v_rows bigint := 0`. Body in this exact order (Landmine #1 — ownership before deduct):
  1. `if v_owner is null then raise exception 'not authenticated'`.
  2. Validate `p_scope in ('unit','tower')` else raise.
  3. If scope='unit': reject with `jsonb_build_object('ok', false, 'reason', 'not_owned')` unless `exists (select 1 from public.inventory where owner = v_owner and unit_id = p_target_id)` (D-16 — note inventory uses columns `owner`/`unit_id`, NOT user_id); and reject `unknown_target` unless p_target_id is in the 6-unit server whitelist.
  4. If scope='tower': reject `unknown_target` unless p_target_id = 'tower_power' (D-01 single track).
  5. Read current level: `select coalesce((select level from public.upgrades where user_id = v_owner and scope = p_scope and target_id = p_target_id), 1) into v_cur_level` (absence = level 1, D-15). Set `v_new_level := v_cur_level + 1`.
  6. `if v_new_level > 5 then return jsonb_build_object('ok', false, 'reason', 'max_level')` (D-10).
  7. Server-derived cost via CASE on (scope, v_new_level) embedding EXACTLY unit {2:75,3:150,4:300,5:600} and tower {2:100,3:200,4:400,5:800} (matches plan-01 UPGRADE_COSTS display mirror; client never supplies amount — D-03/PROG-04). Raise if cost null.
  8. Atomic guarded deduct verbatim from spend_unlock: `update public.wallet set balance = balance - v_cost where owner = v_owner and balance >= v_cost returning balance into v_bal; if not found then return jsonb_build_object('ok', false, 'reason', 'insufficient_funds')`.
  9. Level-transition upsert: `insert into public.upgrades (user_id, scope, target_id, level) values (v_owner, p_scope, p_target_id, v_new_level) on conflict (user_id, scope, target_id) do update set level = v_new_level where public.upgrades.level = v_cur_level` (guard: only advances if current still equals the read level — safe under concurrent retry, Landmine #2).
  10. `get diagnostics v_rows = row_count; if v_rows = 0 then raise exception 'concurrent upgrade detected — retry'` (Landmine #3 — raise rolls back the wallet deduct in the same PL/pgSQL transaction; mirrors report_match_result).
  11. Return `jsonb_build_object('ok', true, 'new_level', v_new_level, 'new_balance', v_bal, 'scope', p_scope, 'target_id', p_target_id)`.
Footer: `revoke all on function public.upgrade_spend(text, text) from public; grant execute on function public.upgrade_spend(text, text) to authenticated`.

Do NOT add a default-row backfill or touch provision_account — absence of a row IS level 1 (D-15), so new and v1.0-migrated accounts need no seeding.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → upgrade_spend RPC | Untrusted client invokes the spend; server must derive cost, verify ownership, and enforce the level transition |
| client → upgrades table | RLS must permit read-own only; all writes denied (deny-by-default) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | upgrade_spend cost | mitigate | Cost embedded as server-side CASE constants; client never passes an amount (p_scope/p_target_id only) — PROG-04/D-03 |
| T-12-02 | Tampering | upgrade of non-owned unit | mitigate | `exists (select 1 from public.inventory where owner = v_owner and unit_id = p_target_id)` ownership check before deduct (D-16) |
| T-12-03 | Tampering | unknown/forged target id | mitigate | Server-side whitelist of 6 unit ids + 'tower_power'; reject `unknown_target` |
| T-12-04 | Tampering | concurrent double-tap level-skip / double-spend | mitigate | `on conflict do update where upgrades.level = v_cur_level` + `get diagnostics row_count` raise-on-zero (rolls back deduct) |
| T-12-05 | Tampering | direct client write to upgrades table | mitigate | RLS: select-own policy only, no insert/update/delete policy (deny-by-default, Pitfall 6) |
| T-12-06 | Elevation of Privilege | spending without auth | mitigate | `auth.uid()` null-guard raises before any read/write |
| T-12-07 | Spoofing | client claims it owns a higher level for a match | accept (interim) | Out of scope this phase: clamp-only guard (plan 04, D-12); server-side ownership-of-level verification deferred to P14 — accepted interim risk, mirroring Phase 11 D-05/D-06 posture |
</threat_model>
