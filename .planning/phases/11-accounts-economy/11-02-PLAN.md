    - credit_wallet_for_user(p_user_id uuid, p_amount bigint, p_key text): internal — REVOKE ALL FROM public,
      do NOT grant to authenticated/anon (only callable by other definer functions / owner). Insert into
      wallet_credits keyed by p_key ON CONFLICT DO NOTHING; if newly inserted, UPSERT wallet balance for p_user_id.
      Used for cross-user/no-session credits (Pitfall 1).
    - spend_unlock(p_unit_id text) RETURNS jsonb: server-derived cost via CASE (assault_bot|thorn_beast|elementalist
      → 100; else RAISE 'unknown unit'); atomic `UPDATE public.wallet SET balance=balance-v_cost WHERE owner=v_owner
      AND balance>=v_cost RETURNING balance INTO v_bal`; IF NOT FOUND → return `{ok:false, reason:'insufficient_funds'}`;
      else `INSERT INTO public.inventory(owner,unit_id) VALUES(v_owner,p_unit_id) ON CONFLICT (owner,unit_id) DO NOTHING`;
      return `{ok:true, new_balance:v_bal, unit_id:p_unit_id}`. NEVER accept a client amount (Pitfall 3). The
      CHECK(balance>=0) on wallet is the backstop for double-tap (Pitfall 5).
    - report_match_result(p_match_id uuid, p_claimed_winner uuid) RETURNS jsonb: INSERT this reporter's row
      ON CONFLICT (match_id, reporter_id) DO NOTHING (idempotent per player, D-07); SELECT the other reporter's
      row; if none → `{status:'pending'}` (D-08, no payout); if other's claimed_winner ≠ p_claimed_winner →
      INSERT match_settlements voided=true,settled=false ON CONFLICT (match_id) DO NOTHING, return `{status:'void'}`

      (settled=true, win_amount=50, loss_amount=15) ON CONFLICT (match_id) DO NOTHING; use
      `GET DIAGNOSTICS v_inserted = ROW_COUNT` (Pitfall 2) — if 0 → `{status:'already_settled'}`; else credit
      both via credit_wallet_for_user(winner,50,'match:'||p_match_id||':win') and (loser,15,'match:'||p_match_id||':loss')
      and return `{status:'settled', winner_id:v_winner_id}`. Reward amounts are server constants only (Pitfall 1/3/4).
    - provision_account(p_user_id uuid) RETURNS void: INSERT wallet(owner,balance) VALUES(p_user_id,0) ON CONFLICT
      (owner) DO NOTHING; PERFORM credit_wallet_for_user(p_user_id, 100, 'welcome:'||p_user_id) (idempotent welcome,
      D-02/D-10). Grant execute to authenticated.
    - Backfill DO $$ block at end of file: FOR each profiles row missing a wallet/inventory, provision wallet+welcome
      grant via credit_wallet_for_user, then FOREACH unit IN unlocked_units[] INSERT inventory ON CONFLICT DO NOTHING
      (D-09 keep earned units free; do NOT add a unit_id CHECK constraint — Pitfall 7 unknown-id safety).
      wins/losses/username are untouched (already in profiles — D-11).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (anon key) → Postgres RLS | All currency/ownership reads cross here; direct writes must be denied |
| client RPC call → SECURITY DEFINER function | Sole authorized write path; runs as definer, bypasses RLS — must self-validate auth.uid() and derive all amounts server-side |
| migration runner → all rows (backfill) | Runs without a user session (auth.uid() NULL); uses explicit p_user_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-03 | Tampering / Elevation | forged wallet/inventory write (client INSERT/UPDATE) | mitigate | RLS deny-by-default (no client write policy) + SECURITY DEFINER RPCs are sole writers (Pitfall 6); proven RED→GREEN by inventory-rls forged-write test |
| T-11-04 | Tampering | client-supplied reward amount (ECON-02) | mitigate | report_match_result/spend_unlock take NO amount param; rewards are SQL constants (Pitfall 3); acceptance grep enforces absence of p_amount |
| T-11-05 | Tampering | double-spend / double-grant (ECON-04) | mitigate | atomic `UPDATE ... WHERE balance>=cost` + `CHECK(balance>=0)` + `match_settlements` UNIQUE(match_id) ON CONFLICT DO NOTHING + GET DIAGNOSTICS (Pitfalls 2/4/5) |
| T-11-06 | Spoofing / Repudiation | settlement collusion / mismatch (D-06) | mitigate | disagreeing reports → voided=true, no payout; two colluding agree-on-false is the ACCEPTED interim risk (D-05), hardened in P14 |
