<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (anon key, under user JWT) → Postgres | Untrusted client attempts reads/writes; RLS is the only gate |
| caller → SECURITY DEFINER function | Function runs as owner, bypassing RLS — search_path and grants are the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-forged-write | Tampering / Elevation | direct client UPDATE of `public.wallet.balance` | mitigate | RLS on, SELECT-own only, NO client write policy → all client writes denied by default; only credit_wallet mutates (proven by plan 05 forged-write test) |
| T-09-cross-account | Information Disclosure / Tampering | reading/writing another user's wallet/inventory/upgrades/match_results/profiles row | mitigate | every policy is `auth.uid() = owner`/`= id`; no `USING (true)` anywhere |
| T-09-searchpath | Elevation of Privilege | credit_wallet definer function | mitigate | `set search_path = ''` + fully-qualified `public.*` names (Pitfall 3) |
| T-09-double-credit | Tampering | retried/replayed credit | mitigate | wallet_credits idempotency ledger + `on conflict (idempotency_key) do nothing` (Pitfall 4) |
| T-09-negbalance | Tampering | balance driven negative | mitigate | `check (balance >= 0)` constraint + amount>0 guard in RPC |
| T-09-rpc-anon | Elevation of Privilege | credit_wallet callable by anon/public | mitigate | `revoke all ... from public; grant execute ... to authenticated` |
</threat_model>
